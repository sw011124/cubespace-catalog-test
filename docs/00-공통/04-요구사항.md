# 요구사항

이 문서로 답하는 것: 무엇을 만들어야 하나(요구 62건)? 무엇이 필수이고 무엇을 줄일 수 있나? 요구 문장과 지금 구현 문서가 다른 곳은 어디인가?

관련: [02-용어](02-용어.md) · [03-미정-결정](03-미정-결정.md)

- 요구 문장은 10/5에 정리한 요구 목록을 그대로 옮겼다. **요구 문장과 구현 문서가 다르면 구현 문서가 기준이다**(3절).
- "(권장안, 확정 전: U-nn)"은 확정 전 권장안이다. 그 값은 [03-미정-결정](03-미정-결정.md) 8절.
- 요구 ID는 REQ-0NN이다. 012~014는 지운 번호라 다시 쓰지 않는다.

- 후순위(K): 컷 날에만 줄인다. 줄여도 요구와 시험 ID는 이 문서에 남긴다.

## 2. 요구 62건

- 요구 칸은 요구 목록의 문장 그대로다.
- 시험 칸에는 지금 문서에 정의가 있는 시험 ID만 적는다. 요구 원문의 패드 시험 PT-n은 Tn, 큐브 시험 CT-3·CT-7·CT-9는 C3·C7·C9로 적었다. 없으면 `-`.

## 3. 이후 결정으로 바뀐 것

요구 문장과 구현 문서가 다르면 구현 문서가 기준이다. 큰 변화는 10/8에 확정한 묶기 재설계다([02-용어](02-용어.md)). 요구 문장의 "제거"는 지금 문서의 "내림", "배정"은 "묶임"이다.

- REQ-006: 화면 제어 모드 첫 진입은 창을 옮기지 않고 패드 지도만 켠다. 템플릿은 큐브를 놓아 묶을 때마다 묶이고 켜진 창(최대 4)에 쓰고, 배치 밖 등록 창은 최소화한다([소프트웨어 04](../04-소프트웨어/04-배치-엔진.md) 4절).
- REQ-008·020: 들고 0.5 s가 넘으면 내림이다. 창을 최소화하고 묶임을 푼다(배정 유지 아님). 같은 자리(`home`)에 다시 놓으면 그 창을 다시 묶는다. 2 s 되돌리기는 뺐다([소프트웨어 03](../04-소프트웨어/03-상태기계.md) 7·10절, [미정 C3]).
