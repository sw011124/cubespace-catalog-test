# 아키텍처

이 문서로 답하는 것: 시스템이 어떤 장치·프로세스로 이뤄지고, 값이 어디서 어디로 흐르며, 판단은 어디서 하나.

관련: [02-용어](02-용어.md) · [03-미정-결정](03-미정-결정.md) · [하드웨어](../01-하드웨어/) · [펌웨어](../02-펌웨어/) · [인터페이스](../03-인터페이스/) · [소프트웨어](../04-소프트웨어/)

상태 표시: `[권장안 U-nn]` 확정 전이지만 이 값으로 구현 · `[미정 …]` 값 없음(잠정이 있으면 그 값으로 구현) · `[실측 필요]` 하드웨어로 정할 값. 목록은 [03-미정-결정](03-미정-결정.md).

## 1. 한 장 그림

```text
[큐브 × 최대 6]  ESP32-S3-Matrix(A1) + 만능기판(A2) + 셀 300 mAh
  S1 접촉 · 버튼 · 배터리 · 도크 감지  →  BLE EVT
  바닥 IR LED: 자기 슬롯(= 등록 번호 0~5)에서만 발광
  8×8 LED: 받은 아이콘만 표시
        │  BLE  패드→큐브 SYNC·CFG·ICON / 큐브→패드 EVT
        ▼
[패드 × 1]  ESP32-S3-Zero
  광센서 7 × 11 = 77(먹스 → ADC) → 슬롯별 차분 → 광학 원시 창(OBS)
  LED 24 × 16 = 384(4체인), 전류 상한 감광
        │  USB CDC  SLIP + CRC-32, 패드→PC 8종 / PC→패드 7종
        ▼
[PC  Windows 11, Electron 동반 앱 한 프로세스]
  gateway ─▶ estimate(좌표 mm) ─▶ cube-events 상태기계 step(state, event) → commands
      ├─▶ engine 배치 ─▶ win-driver(C#, stdio) ─▶ VS Code·Edge·메모장
      ├─▶ 표시 렌더러 ─▶ LED 프레임·ICON ─▶ 패드 ─▶ 큐브 8×8
      └─▶ AI 조정 ─▶ Claude Code·Codex CLI(단계마다 자식 프로세스)
  동반 앱 화면(renderer) ⇄ main 허용 목록 IPC · SQLite 저장소 · JSONL 기록

[도크 6칸]  충전 전용(포고 2핀, 칸별 PTC, 5 V). 통신 없음. 도크에 넣으면 큐브가 BYE 1을 보내고 꺼짐
```

## 3. PC 프로세스

```text
CUBE SPACE.exe   Electron main(단일 인스턴스, 트레이 상주)
                   = apps/client main(창·트레이·IPC 검사·확인 창)
                   + apps/core(상태·판단: estimate·cube-events·engine·표시·AI 조정·저장소)
                   + 입력원 apps/pad-gateway(실제 패드) 또는 apps/pad-sim(가상 패드)
 ├─ renderer(sandbox)          apps/client 화면. main과 IPC만(cube:req, cube:state). 네트워크 포트 없음
 ├─ cube-adapter.exe(C#)       drivers/win-driver. core가 띄우는 상주 자식, stdio NDJSON
 └─ claude.exe · codex.exe     core가 단계마다 띄우는 자식, 셸 없음
```

모두 일반 사용자 권한. core와 입력원은 main 안 모듈이 기본이고, main 이벤트 루프 지연 p99 > 50 ms면 둘을 `utilityProcess`로 뺀다. core와 입력원은 `electron`을 import하지 않아서 옮겨도 코드가 그대로다.

## 4. 값의 흐름 (큐브를 놓아 창을 묶기까지)

| # | 어디서 | 무엇을 | 규격 |
|---|---|---|---|
| 1 | 패드 → 큐브 | SYNC로 패드 시각을 보내고, 큐브는 그 시각에 맞춰 자기 슬롯에 IR을 켬 | [BLE 2·4절](../03-인터페이스/01-BLE.md) |
| 2 | 큐브 → 패드 | S1 접촉 확정 → EVT CONTACT | [BLE 3절](../03-인터페이스/01-BLE.md) |
| 3 | 패드 | 슬롯마다 센서 차분 → ON_PAD면 3 × 4 창 | [펌웨어 03](../02-펌웨어/03-패드-프레임-광학.md) |
| 4 | 패드 → PC | OBS(프레임마다), EVT 중계, LINK | [USB 2절](../03-인터페이스/02-USB.md) |
| 5 | gateway | 검사·순번·시각 복원 → 내부 사건 | [PC 내부 1절](../03-인터페이스/03-PC-내부.md) |
| 6 | estimate | OBS 창 → 좌표 mm | [소프트웨어 02](../04-소프트웨어/02-게이트웨이-좌표.md) |
| 7 | cube-events | 놓임 에지 + 0.5 s·4 mm 안정 → 놓은 점의 맨 위 안 묶인 창 / 최소화 창 옛 자리 / 없으면 선택 팝업 | [소프트웨어 03](../04-소프트웨어/03-상태기계.md) |
| 8 | engine → 어댑터 | 묶이고 켜진 창만 템플릿 배치, 나머지 등록 창 최소화 | [소프트웨어 04](../04-소프트웨어/04-배치-엔진.md), [06](../04-소프트웨어/06-창-어댑터.md) |
| 9 | 표시 → 패드·큐브 | 창 테두리 + 패드 지도(안 묶인 창) + 문제 표시 → LED 프레임, 앱 아이콘 → ICON | [소프트웨어 05](../04-소프트웨어/05-표시.md), [USB 4절](../03-인터페이스/02-USB.md) |

들면: CONTACT 들림 → T_lift 0.5 s → 창 최소화·배정 풂·지난번 프로그램 기억. 버튼: EVT BTN → `?` 큐브면 팝업.

## 5. 구현 원칙

1. **판단은 PC에만.** 패드·큐브는 원시 값과 사건만 보낸다. 규칙이 바뀌어도 펌웨어는 그대로다.
2. **판정 시각은 패드 시각.** "지금" = 마지막 패드 프레임 머리 `t_us`. PC 시계는 표시·지연 측정에만 쓴다.
3. **순수 모듈.** `gateway`·`estimate`·`cube-events`·`engine`·`cube-replay`는 입출력·`Date.now()`·`Math.random()` 금지, 시각은 입력으로 받는다. 같은 입력이면 같은 결과다. 기록 재생과 시뮬레이터가 같은 코드를 쓴다. 펌웨어도 순수 로직을 하드웨어 층과 나눠 PC에서 시험한다.
4. **만든 쪽이 순번·시각을 붙인다.** 패드 `pad_boot_id·pad_seq·t_us`, 큐브 `cube_boot_id·seq·t_pad32`, PC `pc_boot·pc_seq`.
5. **규격 상수는 한 곳.** 펌웨어 `proto.h`, PC `proto.ts`(`packages/protocol`), 둘은 공용 시험 벡터로 맞춘다([04-시험-벡터](../03-인터페이스/04-시험-벡터.md)).
6. **배정·보호·창 연결을 바꾸는 사건 하나 = SQLite 트랜잭션 하나.**
7. **네트워크 포트 없음.** renderer는 main 허용 목록 IPC만. 특권 동작은 OS 확인 창을 거친다 [권장안 U-22].
8. **창을 활성화하지 않는다.** 예외는 전경 창 최소화와 앱 실행으로 생긴 새 창 [권장안 U-24].
9. **실행 중인 AI는 물리 사건에 닿지 않는다.** 물리 사건은 다음 실행 후보만 바꾼다 [권장안 U-35].
10. **기록에 개인 내용을 남기지 않는다.** 창 제목·경로·URL·프롬프트·인증 정보는 기록하지 않는다.

## 8. 저장소

GitHub `CubeSpace-Inha/CubeSpace` 저장소 하나에 문서와 모든 코드를 둔다. 규격을 바꿀 때는 규격 문서([03-인터페이스](../03-인터페이스/))·공용 시험 벡터·PC 코드·펌웨어 코드를 PR 하나로 함께 고친다. 다른 곳에 복사본을 두지 않는다.

```text
CubeSpace/
├── docs/               이 문서들
├── packages/
│   └── protocol/       공용 메시지 형식. 프로그램끼리는 이 형식으로만 주고받는다
├── apps/
│   ├── client/         화면(Electron). 상태를 갖지 않고 core의 스냅샷만 그린다. 닫으면 트레이로
│   ├── core/           상태·판단. 상태를 쓰는 유일한 곳. 모드 인식·좌표 추정·배치 계산·AI 지시·하위 프로그램 감시
│   ├── pad-gateway/    실제 패드 연결(USB). 프레임을 메시지로 바꾸기만 한다. 연결 상태(순번·세션·시각 변환)만 갖고 판단 상태는 없다
│   ├── pad-sim/        가상 패드(개발·시연 대체). gateway와 같은 메시지를 내서 core는 둘을 구분하지 않는다
│   └── server/         서버: AI 확장 목록, 사용자별 설정, 세팅 공유 [미정 S12]
├── drivers/
│   └── win-driver/     창 어댑터(C#, Win32). 시키는 대로 창을 다루고 결과를 알린다. 죽어도 다시 띄우면 된다
├── firmware/           큐브·패드 펌웨어
├── hardware/           큐브·패드 제작 파일과 생성 스크립트
├── optics/             광학 상수 생성(Python)
└── measure/            측정·교정(Python)
```

| 폴더 | 자세히 |
|---|---|
| `packages/protocol/` | TypeScript 코드(USB 프레임 코덱 `proto.ts`, 내부 사건·창 어댑터 메시지·IPC 채널의 타입과 스키마)와 공용 시험 벡터 `vectors/`(생성기 `make_vectors.py`, 결과 `proto_vectors.hex`). 펌웨어(C++)와 win-driver(C#)는 이 패키지를 가져다 쓸 수 없으니 [03-인터페이스](../03-인터페이스/) 규격대로 따로 만들고, 펌웨어는 같은 벡터 파일로 PC와 바이트를 맞춘다([시험 벡터](../03-인터페이스/04-시험-벡터.md)) |
| `apps/`, `drivers/` | 패키지 안 폴더와 기댈 수 있는 곳은 [소프트웨어 01](../04-소프트웨어/01-구성.md) 2절, 서버는 같은 문서 2.1절, 창 어댑터는 [소프트웨어 06](../04-소프트웨어/06-창-어댑터.md) |
| `firmware/` | 소스 구조와 빌드는 [펌웨어 01](../02-펌웨어/01-구조-빌드.md). 빌드는 arduino-cli [권장안 U-06], PlatformIO로 바꿀지 [미정 F8] |
| `optics/`, `measure/` | 절차는 [02-펌웨어/06-광학-보정](../02-펌웨어/06-광학-보정.md) |

배포물은 앱 설치본(`apps/client`가 core·pad-gateway·pad-sim을 함께 묶고, 같은 커밋에서 빌드한 `cube-adapter.exe`를 넣는다), 펌웨어 바이너리(`firmware/`), 서버(`apps/server`, [미정 S12])다. 앱 설치본과 펌웨어 바이너리는 `v0.x.y` 태그와 GitHub Release로 내보낸다.

공통 규칙: `main`은 보호하고 PR로만 병합하며 CI 통과가 필수다. CI는 바뀐 폴더에 맞춰 돈다([소프트웨어 10](../04-소프트웨어/10-재생-시험.md) 4절). 브랜치 이름은 `feat/`·`fix/`·`docs/`. 담당은 팀에서 정하고, 정해지면 `.github/CODEOWNERS`에 폴더별로 넣는다. AI 확장 목록은 `.github/workflows/catalog.yml`이 매일 종류별 갱신 PR을 연다. skill PR은 검사·검토를 통과하면 자동 병합하고, MCP PR은 `.github/CODEOWNERS`의 `apps/server/catalog/items/mcp/` 검토자가 병합한다([설계 ai-preset-builder](../specs/ai-preset-builder.md) 4.5·4.7절).
