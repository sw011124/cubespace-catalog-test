# 동반 앱

이 문서로 답하는 것: 동반 앱의 메뉴와 화면마다 보이는 것·할 수 있는 것, 선택 팝업 창, 디자인 토큰, 보안 골격 규칙.

관련: [시안 pad-home.html](시안/pad-home.html) · [01 구성](01-구성.md) · [03 상태기계](03-상태기계.md) 9절 · [07 AI 실행](07-AI-실행.md) · [09 저장·기록](09-저장-기록.md) · [PC 내부 3 렌더러 ↔ main IPC](../03-인터페이스/03-PC-내부.md)

화면 구성·보이는 것·할 수 있는 것은 시안 [시안/pad-home.html](시안/pad-home.html)이 기준이다(3.7 MB 단일 HTML, 글꼴 포함, 브라우저로 연다). 시안 동작이 묶기 재설계·요구 원문([00-공통/04](../00-공통/04-요구사항.md))과 다른 줄에는 `[미정: 시안과 규칙 충돌]`을 달았다.

## 1. 틀과 메뉴

| 항목 | 시안 |
|---|---|
| 화면 틀 | 한 창 안에서 보기를 바꾼다(`data-view` 0~4). 라우터 라이브러리 없음 |
| 주 메뉴 | 왼쪽 떠 있는 세로 막대(폭 64 px, 아이콘만, 올리면 이름 말풍선): 홈 · 창 · AI 모드 · 시뮬레이션 · 설정 [미정: 시안과 규칙 충돌] (요구 원문은 메뉴 넷, 시뮬레이션 없음) |
| 막대 아래 | 연결 줄 `PC ━ 패드 ━ 큐브` + 슬롯 점 6개 + `n/6`(끊기면 `판정 동결`), 알림 종(건수), 테마 버튼(화이트·블랙) |
| 선 규칙 | 연결 = 초록 실선(흐름 움직임), 끊김 보류·응답 없음 = 주황 끊어진 선, 꺼짐·없음·판정 동결 = 회색 점선, 막힘 = 빨강. 색과 모양을 함께 쓴다(REQ-017) |
| 연결 줄·종 누름 | 상태 서랍(2절). 슬롯 점을 누르면 그 큐브로 확대 |
| 테마 | 처음엔 시스템 설정, 버튼으로 바꾸면 기억(`localStorage` `cs-theme`)(REQ-065 ⑨) |
| 좁은 화면 | 720 px 이하면 메뉴를 아래 막대로, 오른쪽 6칸을 그 위 줄로. 1180 px보다 좁으면 6칸을 띠로 |
| 접근성 | 키보드 조작, 초점 링 2 px, `aria-label`, 클릭 영역 44 px 이상, `prefers-reduced-motion`이면 움직임 끔. 밖에서 온 문자열은 텍스트로만(REQ-052) |
| 상태 견본 | 기본 = 개발 견본 `ok`에 보호·충전 필요·꺼짐을 섞은 것. `?state=padlost` = 패드 세션 끊김(판정 동결, 알림 `pad_lost`) |

- 렌더러는 `cube:state`의 `{ver, s}`에서 `ver`가 큰 것만 남긴다. 모르는 코드·상태는 "알 수 없음"으로 그린다. `s` 필드 후보는 [PC 내부](../03-인터페이스/03-PC-내부.md) 3절의 `s` 표다.
- 구현 라우팅: react-router `BrowserRouter`로 `/` 앱, `/template` 부품 카탈로그(개발 때만)를 둔다([01 구성](01-구성.md) 5절). 시안의 보기 전환(`data-view`)을 `/` 안에서 어떻게 나눌지는 화면을 만들 때 정한다.
- 개발 견본 이름은 시안 견본과 같은 이름으로 맞춘다(`ok`, `padlost` 등).
- 알림에는 닫기 버튼이 없다. 큐브와 무관한 알림은 화면 + 작업 표시줄 깜박임만 [권장안 U-25]. 본창이 트레이로 숨겨져 있으면 작업 표시줄 단추가 없으므로 트레이 아이콘 바꿈·알림으로 대신한다 [실측 필요].

## 2. 홈

| 부분 | 보이는 것 | 할 수 있는 것 |
|---|---|---|
| 패드 | 화면 전체 배경이 패드. 3:2, LED 24 × 16 점, 패드 위쪽으로 올라가는 USB 선 하나(연결 상태 선 규칙). 판정 동결이면 전체를 흐림 | |
| 패드 LED | 창 모드 큐브의 창 영역 테두리만 영역 색으로. AI 모드 영역은 끔 [미정: 시안과 규칙 충돌] (패드 지도 층이 없다, [05](05-표시.md) 2절) | |
| 큐브 | 실제 mm 좌표에 35 mm 축척 정사각형, 윗면 8 × 8 아이콘(앱·프로필·등록·상태), 두꺼운 옆면. 아래 줄에 이름·배터리(30 % 이하 `충전 필요`, 10 % 이하 빨강)·상태 배지(가동·미배정이 아닐 때) | 올리거나 초점 → 세 갈래, 누름 → 확대 |
| 세 갈래 | 그 큐브만 선명해지고 패드·무선 / 창(영역 n, 사용 중) / AI(종류, 사용 중) 세 카드가 선으로 펼쳐짐. 지금 모드 가지만 흐름 강조. 맡은 것이 없으면 점선 "없음". 창·AI 가지는 무선 상태와 대상 상태 중 나쁜 쪽 | |
| 오른쪽 6칸 | 연결됐지만 패드 밖인 큐브, 그 뒤 도크에서 충전 중인 큐브(번개, 마지막 잔량 막대). 연결 안 된 큐브(무선 끊김·버튼 끔·저전압)는 그리지 않음(연결 줄 점에만) | 누름 → 확대 |
| 확대(노드 그래프) | 위 막대: 뒤로, 큐브 이름, 이 큐브의 모드 탭 `창 \| AI`, `Esc`. 왼쪽 열: 패드(보기만)·창·AI 노드. 창·AI 노드의 `+N`을 누르면 오른쪽에 이을 수 있는 후보(창: 연결·최소화·재실행 가능 창, AI: 프로필) | 큐브마다 모드 바꾸기 [미정: 시안과 규칙 충돌] (모드는 전체 하나, REQ-034). 후보를 누르거나 끌어 놓아 창·AI 교체, 다른 큐브 것이면 맞바꿈 [미정: 시안과 규칙 충돌] (배정은 큐브를 놓아서만, (묶기 재설계, [03 상태기계](03-상태기계.md)). 연결 끊긴 큐브는 보기만 |
| 상태 서랍 | 패드(USB·입력원, 펌웨어, 불량 센서, 큐브 등록·연결·활성 최대 4), 알림(코드 칩 + 문구), 창 연결(창 이름·담당 큐브·상태 배지, 재실행 가능이면 버튼), 최근 오류 | '기록 초기화'(OS 확인 창) |
| 홈 로고 | 아래 가운데 CUBE SPACE. 홈으로 돌아올 때 카드·큐브가 튀어 오르는 움직임 | |

- 장치 추가는 3단계(패드 연결 → 큐브 등록 → 위치 확인)이고 설정 화면에 있다(6절).
- 첫 실행 안내 2단계 문구: "큐브를 패드 위 창 자리에 올려 보세요 — 패드에 빛나는 구역이 지금 열린 창입니다"(묶기 재설계). 시안에는 첫 실행 안내가 없다.

## 3. 창

시안(`pad-home.html`) 안에 넣어 둔 이전 시안 화면(원래 파일 이름 `cube-space (3).html`)을 그대로 띄운다(창 쪽, `data-page="win"`).

| 부분 | 보이는 것 | 할 수 있는 것 |
|---|---|---|
| 큐브 카드 | 패드 위 큐브(최대 4) 칸: 아이콘, 이름, 상태, 맡은 창(꺼짐 표시) 또는 "묶인 창 없음", 빈 칸. 아래 "패드 밖" 줄 | 누르면 아래 설정이 그 큐브로 |
| 큐브 설정 | 패드 위·밖, 배터리, 묶인 창 행 | 창 켜기·끄기, 교체, 해제 [미정: 시안과 규칙 충돌] (교체는 앱에서 창 고르기) |
| | 지난번 프로그램(`?` 큐브를 누르면 먼저 추천) | 보기 |
| | 고정 프로그램(빈 곳에 놓으면 고르지 않고 바로 열기) | 고르기 [미정: 시안과 규칙 충돌] (요구 원문·묶기 재설계에 없음) |
| | 큐브 버튼(배치된 큐브 짧게: 켜기·끄기 / 다시 고르기)과 상태 × 입력 표(한 번 / 꾹 0.6 s): 패드 밖 = 동작 없음, `?` = 고르는 창(고정이면 바로 열기), 고르는 창 = 맨 위 항목 / 취소, 배치됨 = 켜기·끄기 / 풀고 다시 고르기 | 고르기 [미정: 시안과 규칙 충돌] (REQ-063 길게는 1 s, 길게 기본값은 없음) |
| 열린 창 | 대상 모니터 `◀ ▶`, 창마다 앱 아이콘·이름·제목·지난 시간 | 묶인 창: 켜기·끄기. 안 묶인 창: 왼쪽·오른쪽 절반, 최소화·올리기, 항상 위, 닫기 [미정: 시안과 규칙 충돌] (모니터 1대 [권장안 U-26], 앱이 창을 직접 옮기거나 닫는 기능은 요구 원문에 없음) |
| 모드(모양 모드) | 저장된 모드 띠(패드 칸 그림, 이름, 프로그램 아이콘), 모드 카드(큐브 수, 실행 중) | 새 모드·편집: 칸을 눌러 큐브를 놓고 열 프로그램을 고름(최대 4), 이름으로 저장·덮어쓰기, 삭제 [미정 C2] |

- 창 제목은 메모리에서만 그리고 저장·기록하지 않는다(REQ-018).
- 관리자 권한 창은 "관리자 권한으로 실행된 창은 CUBE SPACE가 옮길 수 없습니다"와 함께 보인다(REQ-029).

## 4. AI 모드

| 부분 | 보이는 것 | 할 수 있는 것 |
|---|---|---|
| AI에게 맡길 일 | 여러 줄 입력(2,000자), 예시 칩(기능 만들기·버그 고치기). 대화창은 실행 전 목표 구체화용(REQ-062) | 입력 |
| 프리셋 | 이름·용도·구성 칩, 배정된 큐브 색 표지(없으면 `배정 없음`) | 편집(✎), 눌러서 큐브 고르기 [미정: 시안과 규칙 충돌] (AI 후보는 큐브를 놓아야 생김, REQ-040) |
| 아래 막대 | 꼼꼼함 3단(가볍게 / 균형 / 꼼꼼하게 = 사용 강도, REQ-061) | `✦ 추천으로 채우기`(비어 있는 역할 채움), `▶ 시작`(맡길 일이 있고 실행 중이 아닐 때) |
| 시작 전 검증 | 패드 연결, 프로젝트 1, 에이전트 1~2, 중복 없음 | 어긋나면 거절. 시안은 자동 채움으로 흉내 [미정: 시안과 규칙 충돌] (REQ-039 검증·코드 표시, [07](07-AI-실행.md) 3절) |
| 진행 카드 | 단계 `n / m`, 단계 목록, 참여 구성. 끝나면 "다 끝났어요" | `중지`, 끝나면 `새 작업`. 실행 중 바꾼 배정은 다음 작업부터 |
| 고급 설정 ▾ | 도구 탭 5개, 큐브에 담을 구성(큐브를 고르고 전환 후보 추가), 전환 가능 목록 | 프로필 만들기·편집·묶음 |

- 실행 상태 6개·대기 사유·종료 사유·사용량·바뀐 파일 목록은 진행 카드에 더한다([07](07-AI-실행.md) 5·7절). 대기 응답의 계속은 OS 확인 창.
- 직접 합친 프리셋은 저장할 때 충돌(프로젝트 2개 이상, 에이전트 3개 이상, 같은 역할, 중복)을 검사하고 저장을 막는다(REQ-061).
- 프리셋 만들기(용도 → 요구 카드 칩 첨삭 → 고르기·배치 → 미리보기 → 저장)는 [설계 ai-preset-builder](../specs/ai-preset-builder.md) 7절이다. 요구 카드의 능력 칩은 필수와 선택으로 나누고 선택 칩은 사용자가 켜고 끈다. `✦ 추천으로 채우기`는 이 흐름의 고르기·배치를 쓴다.

## 5. 시뮬레이션

- 시안은 안에 넣어 둔 이전 시안 화면(원래 파일 이름 `cube-space (4).html`)을 견본 데이터로 그대로 띄운다(장치 상태, AI 작업, 패드에 큐브 끌어 놓기, 큐브 배정). 홈 큐브와 이어지지 않는다.
- 구현: 개발판에서만 메뉴에 보이고, 시뮬레이터 입력(`--source=sim`, [10](10-재생-시험.md) 1절)을 `dev.*` 채널로 조작하는 화면으로 둔다 [미정: 시안과 규칙 충돌] (요구 원문 메뉴에 없음).

## 6. 설정

시안의 설정은 장치 추가 + 창 쪽 설정 쪽(`data-page="set"`: 규칙 · 프로그램 · 상태 아이콘)이다.

| 부분 | 보이는 것·할 수 있는 것 |
|---|---|
| 장치 추가 | 패드 연결 → 큐브 등록 → 위치 확인 3단계. 슬롯 = 등록 번호 0~5, 슬롯이 차면 시작 불가. 후보가 정확히 1개일 때만 등록(2개 이상 "등록할 큐브 하나만 켜세요", 0개 "큐브를 켜세요"). 등록 해제는 두 번 눌러 확정(REQ-019) |
| 규칙: 화면 나누기 | 켜진 묶인 창 수별: 2개 = 큐브 위치 따라 / 반반, 3개 = 왼쪽 크게 / 세로 3칸, 4개 = 4칸 / 세로 4칸 [미정: 시안과 규칙 충돌] (요구 원문은 템플릿 하나씩, [미정 C4]) |
| 규칙: 큐브를 내렸을 때 | 묶인 창 최소화 / 닫기, 되돌리는 시간(초), 제자리로 볼 거리(mm) [미정: 시안과 규칙 충돌] (내림 = 늘 최소화, 되돌리기 없음 [미정 C3], 짧은 들기는 T_lift 0.5 s) |
| 규칙: 모드 | 붙어 있다고 볼 틈(mm) [미정 C2] |
| 규칙: PC 켤 때 | 모드 바로 실행(기본 켬, 켜면 무엇을 열지 미리 보임). 요구 원문의 이름은 `PC를 켤 때 모드 자동 실행`, 끄면 늘 `?`(묶기 재설계) |
| 규칙: 프리셋 | 켤 때 프로그램을 열어 두기만(큐브는 `?`), 이름·앱 추가·빼기·삭제 [미정: 시안과 규칙 충돌] (REQ-064는 배정 불변·실행 안 함) |
| 규칙: 예외 | 항상 위 창은 묶지 않기(토글), 묶지 않을 앱(그 위에 놓으면 빈 곳처럼 팝업) [미정: 시안과 규칙 충돌] (항상 위 창은 늘 제외) |

## 7. 선택 팝업 창

| 항목 | 규칙 |
|---|---|
| 창 | 본창과 다른 작은 `BrowserWindow`. 항상 위, 테두리 없음, 작업 표시줄에 안 보임. 같은 `webPreferences`·CSP·preload |
| 위치 | 상태기계가 준 `anchor_px`(큐브 자리에 해당하는 화면 점) 근처, 작업 영역 안으로 밈. 본창을 앞으로 부르지 않는다. `anchor_px`는 물리 px이고 `BrowserWindow`는 DIP라 `screen.screenToDipPoint`로 바꾼 뒤 `setBounds`한다(배율 125·150 %에서 어긋남 방지) |
| 내용 | 위부터 `lastProgram` → 안 묶인 열린 창(떠 있음 → 최소화) → 최근 프로그램(3개까지, `lastProgram` 빼고) → 검색. 시안은 프로그램 설정 `고르는 창 순서`가 `즐겨찾기 먼저`면 맨 위에 즐겨찾기 묶음을 더 둔다(기본 `최근 먼저`) [미정: 시안과 규칙 충돌]. 앱 이름·아이콘만, 창 제목은 메모리에서만 |
| 조작 | 클릭·Enter = 고름, Esc·바깥 누름(창 blur) = 닫음. 큐브 버튼 짧게 = 맨 위. 팝업은 초점을 못 받을 수 있다(큐브 입력은 USB라 앱이 마지막 입력 프로세스가 아니어서 `SetForegroundWindow` 제한에 걸림). 그래서 `showInactive()`로 띄우고, Enter·Esc·blur 없이도 클릭·큐브 버튼으로 고르고 큐브 들기(CONTACT UP, [03 9절](03-상태기계.md))로 닫히게 한다 |
| 보내는 값 | 고른 항목 id(창 id 또는 앱 ID)만. 실행 경로·인자는 렌더러가 만들 수 없다(REQ-052) |
| 채널 | 허용 목록에 `popup.pick{cube, item}`, `popup.close{cube}`를 더한다(이름·스키마는 잠정안 [미정 S2]). 목록·스키마·처리기를 같은 커밋에서 고친다 |
| 동반 앱 창 | 배치·지도·묶기 대상이 아니다(`exclude_pids`) |
| 검색 | 등록 앱 이름만 찾는다 [미정 C1] |

## 9. 보안 골격 규칙

`apps/client`에서 처음부터 이 규칙대로 만들고 풀지 않는다. 첫 뼈대는 개발 서버로만 열고, `app` 스킴 적재는 포장 단계에서 넣는다([01 구성](01-구성.md) 5절).

| 대상 | 값 |
|---|---|
| `webPreferences` | `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `nodeIntegrationInWorker: false`, `webSecurity: true`, `webviewTag: false`, `devTools: !app.isPackaged`, `preload`. 기본값과 같아도 모두 적는다 |
| 적재 | `app` 스킴(standard·secure·supportFetchAPI). 호스트 ≠ `cube`면 404. `resolved = path.resolve(root, '.' + decodeURIComponent(pathname))`(디코딩 예외 400), `path.relative(root, resolved)`가 비었거나 `..`로 시작하거나 절대 경로면 404, 아니면 `net.fetch(pathToFileURL(resolved))` |
| CSP(배포판) | `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. 개발판은 `connect-src 'self' ws://localhost:<포트>`만 다름 |
| 탐색·창 | `will-navigate` 막음, `setWindowOpenHandler → deny`, `will-attach-webview` 막음. 팝업 창은 main이 직접 만든다. 시안의 `iframe srcdoc` 화면은 구현에서 React 화면으로 바꾼다 |
| 권한 | 요청·확인 처리기 모두 거부. 복사는 main 채널 `clipboard.write{text ≤ 64 KiB}` |
| 외부 열기 | `shell.openExternal` 0곳 |
| preload | `window.cube.invoke(ch, body)`, `window.cube.onState(cb)` 두 함수만 |
| IPC | `ipcMain.handle('cube:req')` 1개, `ipcMain.on` 0개. 검사 순서: origin(`APP_ORIGIN`) → 허용 목록 → 본문 크기(65,536 B) → 채널별 ajv(`additionalProperties: false`) → 특권이면 네이티브 확인 창 → 처리기(대기 10 s). 채널 목록·오류 코드는 [PC 내부 3](../03-인터페이스/03-PC-내부.md) |
| 재전송 | 렌더러는 자동 재전송하지 않는다. `request_id`는 `ai.start`만, 나머지 변경은 멱등 또는 `busy` |
| 로그 | 요청마다 채널·결과 코드·처리 ms만. 본문 없음 |
| 밖에서 온 문자열 | React 텍스트 노드로만. `toDisplay`: CSI·OSC·ESC·C0(`\t`·`\n` 밖)·C1 삭제, 양방향 제어 문자는 `⟨U+202E⟩` 꼴로, 블록 200,000자 넘으면 자르고 "(잘림…)". 링크를 만들지 않는다 |
| 금지 문자열 | 소스에 `nodeIntegration: true`, `contextIsolation: false`, `sandbox: false`, `webSecurity: false`, `dangerouslySetInnerHTML`, `innerHTML`, `openExternal`, `file://`, `startsWith(root`, `.credentials.json`, `auth.json`, `CLAUDE_CODE_OAUTH_TOKEN` 0건(주석 포함, `test/rules.test.ts`) |
| 단일 인스턴스 | `requestSingleInstanceLock()` 실패면 종료, `second-instance`에서 기존 창 |
| 판 | Electron 정확 고정, 퓨즈는 바꾸지 않음 |

### 특권 동작(OS 확인 창)

렌더러는 후보 값만 보내고 main이 `dialog.showMessageBox`로 확인한 뒤 저장·실행한다. 취소면 아무것도 하지 않는다.

| 동작 | 채널 | 확인 창에 보이는 것 |

| MCP 등록 | `mcp.register_begin` | 실행 파일(네이티브 선택), 인자, 허용 도구, SHA-256 |
