# 구성

이 문서로 답하는 것: PC 쪽은 어떤 프로세스와 폴더·패키지로 나뉘고 데이터가 어떻게 흐르나, 서버는 무엇을 맡나, 개발 환경은 무엇이고 무엇부터 만드나.

관련: [02 게이트웨이·좌표](02-게이트웨이-좌표.md) · [03 상태기계](03-상태기계.md) · [04 배치 엔진](04-배치-엔진.md) · [05 표시](05-표시.md) · [06 창 어댑터](06-창-어댑터.md) · [07 AI 실행](07-AI-실행.md) · [08 동반 앱](08-동반-앱.md) · [09 저장·기록](09-저장-기록.md) · [10 재생·시험](10-재생-시험.md) · [PC 내부 인터페이스](../03-인터페이스/03-PC-내부.md)

## 1. 프로세스

| 프로세스 | 하는 일 | 통신 |
|---|---|---|
| Electron main(`apps/client`) | 단일 인스턴스, 트레이 상주, 창·IPC 검사·특권 확인 창. core와 입력원을 안에 띄운다 [권장안 U-22] | 함수 호출 |
| 렌더러(React, `apps/client`) | 동반 앱 본창, 선택 팝업 창. `sandbox: true` | `cube:req`·`cube:state`([PC 내부 3](../03-인터페이스/03-PC-내부.md)) |
| preload | `window.cube.invoke`·`window.cube.onState` 두 함수만 노출 | 같음 |
| core(main 안, `apps/core`) | 좌표 추정, cube-events, 배치 엔진, 표시 렌더러, AI 조정, 저장소, 어댑터 클라이언트, 서버 연결 | 함수 호출 |
| 입력원(main 안) | 실제 패드 `apps/pad-gateway`(USB는 `serialport`) 또는 가상 패드 `apps/pad-sim`. 둘 중 하나만 | 함수 호출([PC 내부 1](../03-인터페이스/03-PC-내부.md)의 같은 사건) |
| `cube-adapter.exe`(C#) | core가 띄우는 상주 자식. 창 열거·적용·판정·감시·앱 실행. 코드는 `drivers/win-driver` | stdio NDJSON([PC 내부 2](../03-인터페이스/03-PC-내부.md)) |
| `claude.exe`·`codex.exe`·판정 테스트 | 단계마다 띄우는 자식 | 인자·stdin([PC 내부 4](../03-인터페이스/03-PC-내부.md)) |

- 포트를 열지 않는다. TCP·UDP LISTEN 0, `ws`·`express`·HTTP 서버 의존성 금지(REQ-052) [권장안 U-22]. 서버(`apps/server`)와는 core가 밖으로만 연결한다(2.1절).
- main 이벤트 루프 p99가 50 ms를 넘으면(S-E2) core와 입력원을 `utilityProcess.fork()`로 뺀다. 둘은 `electron`을 import하지 않아서 코드는 그대로고, 렌더러 쪽 IPC도 그대로다 [실측 필요].
- 창을 닫으면 트레이로 간다(창 제어 계속). 트레이 "종료"만 앱을 끝낸다.
- 종료 순서: 활성 AI 실행이면 확인 창 → CLI·판정 `taskkill /PID <pid> /T /F` → LED_OFF → 어댑터 stdin 닫기 → SQLite 닫기 → `app.quit()`. 상한 3 s(활성 실행이면 +15 s), 넘으면 `app.exit(0)`.
- 모든 자식: `spawn(file, args, { shell: false, windowsHide: true, detached: false })`. 부모 환경을 물려주지 않는다([07 AI 실행](07-AI-실행.md) 4절, [PC 내부 4](../03-인터페이스/03-PC-내부.md) R5).
- 어댑터가 관리자 권한으로 떠서 종료 코드 3이면 창 제어와 AI 시작을 모두 막는다.

## 2. 폴더와 패키지

PC 쪽 코드는 CubeSpace 저장소의 `packages/protocol`, `apps/`(client·core·pad-gateway·pad-sim·server), `drivers/win-driver`에 둔다. TypeScript 패키지는 pnpm workspace 하나로 묶는다(`pnpm-workspace.yaml`: `packages/*`, `apps/*`). 저장소 전체 구성은 [아키텍처 8](../00-공통/01-아키텍처.md).

| 폴더 | 책임 | 기댈 수 있는 곳 |
|---|---|---|
| `packages/protocol/src/` | 메시지 형식: USB 프레임 코덱 `proto.ts`(SLIP·CRC·시각 복원·값 검사), 내부 사건 타입([PC 내부 1](../03-인터페이스/03-PC-내부.md)), 창 어댑터 메시지([PC 내부 2](../03-인터페이스/03-PC-내부.md)), IPC 채널 목록·스키마([PC 내부 3](../03-인터페이스/03-PC-내부.md)) | 없음 |
| `packages/protocol/vectors/` | 공용 시험 벡터 생성기 `make_vectors.py`와 결과 `proto_vectors.hex`([시험 벡터](../03-인터페이스/04-시험-벡터.md)) | |
| `apps/core/src/engine/` | 배치 엔진: 분할 트리, 템플릿, 접힘, 밀기, 최소 크기, 점 판정, 패드 지도 | 없음 |
| `apps/core/src/estimate/` | 광학 원시 창 + 보정 → 패드 mm 좌표 | 없음 |
| `apps/core/src/cube-events/` | 상태기계 `step(state, event)` | `engine` |
| `apps/core/src/` 나머지 | 서비스 셸(사건 루프, SQLite, JSONL 기록, `cube:state` 만들기), 표시 렌더러, AI 조정 | 위 셋, `protocol` |
| `apps/core/src/driver/` | 창 어댑터 클라이언트: 띄우기, 명령 보내기·결과 받기, ping, 재시작([06](06-창-어댑터.md) 1절) | 같음 |
| `apps/core/src/remote/` | 서버 연결. 밖으로만 | 같음 |
| `apps/pad-gateway/src/gateway/` | USB 프레임 검증, 순번, 재부팅·세션, 시각 변환([02](02-게이트웨이-좌표.md)) | `protocol` |
| `apps/pad-gateway/src/serial/` | 패드 USB 열기·읽기·쓰기(`serialport`), 패드 시험 펌웨어 CSV 입력 | `gateway`, `protocol` |
| `apps/pad-sim/src/` | `cube-replay`: 시뮬레이터(장면 시나리오 → `obs.window`)와 기록 재생([10](10-재생-시험.md)) | `protocol` |
| `apps/client/src/main/` | 창·트레이·단일 인스턴스, 보안 골격, IPC 검사, 특권 확인 창, 입력원 고르기(`--source`), core와 입력원 띄우기 | `core`, `pad-gateway`, `pad-sim`, `protocol` |
| `apps/client/src/preload/` | `invoke`·`onState` 두 함수 | `protocol`의 IPC 계약만 |
| `apps/client/src/renderer/` | 동반 앱 화면(React). `index.html`·`main.tsx`·`App.tsx`와 `styles/`·`layout/`·`components/`·`hooks/`·`model/`·`screens/`·`template/` | `protocol`의 IPC 계약만 |
| `test/`(저장소 뿌리) | `rules.test.ts`(3절) | |

`drivers/win-driver/`: C# `cube-adapter.exe`(창 열거·적용·판정·감시·앱 실행, [06](06-창-어댑터.md)).

- core는 실제 패드(pad-gateway)와 가상 패드(pad-sim)를 구분하지 않는다. 둘 다 [PC 내부 1](../03-인터페이스/03-PC-내부.md)의 같은 사건을 내고, `obs`의 좌표는 core가 받을 때 `estimate`로 채운다. 어느 쪽을 쓸지는 client main이 시작 인자 `--source`로 고른다([10](10-재생-시험.md) 1절).
- 판단 상태는 core에만 있다. pad-gateway는 연결 상태(순번·세션·시각 변환)만, client는 화면 상태만 갖는다.

빈 폴더를 먼저 만들지 않는다. 파일이 생길 때 폴더도 생긴다.

### 2.1 서버(`apps/server`)

창 제어와 AI 실행은 서버 없이 PC 안에서 끝난다. 서버는 PC 하나로는 할 수 없는 세 가지를 맡는다. 첫 판은 AI 확장 목록과 사용자별 설정이고, 세팅 공유·추천은 다음 판이다. 회원가입·로그인은 없고 서버가 발급한 키로 사용자를 구분한다(아래). 언어·프레임워크·DB·호스팅·착수 시점은 정하지 않았다 [미정 S12].

| 역할 | 판 | 하는 일 |
|---|---|---|
| AI 확장 목록 | 첫 판 | AI 모드가 쓰는 skill·MCP를 모아 두고 판을 올린다. 목록은 저장소 `apps/server/catalog/`에 있고 GitHub Actions가 매일 갱신 PR을 연다([설계 ai-preset-builder](../specs/ai-preset-builder.md) 4절). 앱은 새 판을 내지 않고 목록과 갱신을 받는다. 키 없이 읽는다. 서버가 생기기 전에는 앱 설치본에 목록 사본을 넣는다 |
| 사용자별 설정 | 첫 판 | 키마다 동반 앱 설정, AI 프리셋, 고른 확장을 보관한다. 같은 키를 넣은 다른 PC에서 이어 쓴다 |
| 세팅 공유·추천 | 다음 판 | 사용자가 세팅 묶음을 공개하면 다른 사용자가 별(GitHub star처럼)을 준다. 별 순으로 추천받아 가져다 쓴다. 별은 키 하나에 하나 |

키:

| 항목 | 규칙 |
|---|---|
| 발급 | 사용자가 설정 동기화를 처음 켤 때 core가 `POST /keys`로 받는다. 서버는 무작위 130비트를 만들어 Crockford Base32 26자로 응답에 한 번만 싣는다. 화면에는 5자씩 끊어 보인다(`XXXXX-XXXXX-…`) |
| 서버 보관 | 원문은 저장하지 않고 SHA-256 해시만 둔다. 무작위 130비트라 솔트 없는 해시로 충분하다 |
| PC 보관 | client main이 Electron `safeStorage`(Windows DPAPI)로 암호화해 `%LOCALAPPDATA%\CubeSpace\server-key.bin`에 둔다. 앱을 켤 때 풀어서 core `remote/`에 메모리로만 넘긴다. DPAPI는 다른 Windows 사용자는 막지만 같은 사용자의 다른 프로그램은 막지 못한다 |
| 쓰기 | 설정 요청마다 HTTPS `Authorization: Bearer <키>`. 서버는 해시로 찾는다 |
| 다른 PC | 설정 화면에서 키를 보고 옮겨 적은 뒤, 다른 PC에서 "키 넣기"로 넣으면 그 키의 설정을 받는다. 키는 사용자가 "키 보기"를 누를 때만 보인다 |
| 잃어버림 | 되찾을 수 없다. 새 키를 받으면 서버 설정은 빈 상태에서 시작한다(PC에 있는 설정은 그대로) |
| 지우기 | `DELETE /me`로 키와 그 설정을 지운다. 키가 새어 나갔으면 지우고 새 키를 받는다 |
| 막을 것 | 키 발급은 IP마다 횟수를 제한한다. 값과 방법, 오래 안 쓴 키를 지우는 기준은 [미정 S12] |

```text
apps/server/
  src/keys/       키 발급, 해시 대조
  src/catalog/    AI 확장 목록 크롤러(검사·Claude 검토·태그), 항목 형식 검사
  catalog/        승인된 목록(items/<kind>/<id>.json), 칩 어휘, 크롤러 상태
  src/settings/   키별 설정
  src/presets/    세팅 묶음 공개·별·추천·가져오기(다음 판)
  src/api/        앱이 부르는 HTTPS API
  db/             스키마·마이그레이션
  test/
```

자료(잠정):

| 표 | 필드 |
|---|---|
| `keys` | `key_hash, created_at, last_used_at` |
| `extensions` | `id, kind: skill\|mcp, name, version, sha256, source, updated_at`와 `commit, package{type,id,version,integrity,deps}, stars, forks, license, scorecard, verified_at, tags, rw, tools[{name,rw}], review, approval, status`([설계 ai-preset-builder](../specs/ai-preset-builder.md) 4.8절, `apps/server/src/catalog/item.ts`) |
| `settings` | `key_hash, body, ver, updated_at` |
| `presets`(다음 판) | `id, owner_key_hash, title, body(설정 + 확장 참조), public, stars, updated_at` |
| `stars`(다음 판) | `key_hash, preset_id`. 둘을 묶어 유일 |

API(잠정 [미정 S12]):

| 역할 | 요청 |
|---|---|
| 키 | `POST /keys`(키 없이, 응답 `{key}`), `DELETE /me` |
| AI 확장 목록 | `GET /extensions?since=<판>`(키 없이) |
| 사용자 설정 | `GET /me/settings`, `PUT /me/settings`. `PUT`은 마지막으로 받은 `ver`를 싣고, 서버 판과 다르면 409로 거절한다(다른 PC가 먼저 고침). 그때 앱은 받기·덮어쓰기를 묻는다 |
| 세팅 공유·추천(다음 판) | `GET /presets?sort=stars`, `GET /presets/{id}`, `POST /presets`, `POST /presets/{id}/star` |

지킬 것:
- 앱은 포트를 열지 않는다(REQ-052). 서버와는 core가 `remote/`로 밖으로만 연결하고, 렌더러는 직접 연결하지 않는다(CSP `connect-src 'none'`, [08](08-동반-앱.md) 9절). 화면에 필요한 값은 `cube:state`와 IPC로 받는다([PC 내부 3](../03-인터페이스/03-PC-내부.md)).
- 서버에서 받은 skill·MCP도 지금 등록 규칙을 그대로 거친다: 로컬 stdio만, 허용 도구 목록, 특권 등록(OS 확인 창)([07](07-AI-실행.md)). MCP npm 패키지는 목록의 integrity와 맞는 판만 설치 스크립트 없이 설치하고 고정 판 `node.exe` 절대 경로로 띄운다 [권장안 U-103]. 내려받은 파일의 해시가 목록 값과 다르면 버린다.
- 기록에 남기지 않는 것(창 제목·파일 경로·URL·프롬프트·대화·인증 정보, REQ-018)은 서버에도 올리지 않는다. 올리는 항목은 사용자가 보고 고른다.
- 키는 인증 정보다. 로그·기록·오류·`cube:state`에 넣지 않는다(REQ-018).
- 서버가 없거나 끊겨도 창 제어와 AI 실행은 이미 받아 둔 값으로 돈다.
- 공개 세팅(다음 판)은 승인된 목록 id만 가리키게 해서 악성 확장이 끼어들지 못하게 한다 [미정 S12].

## 3. 순수 모듈 규칙

대상: `packages/protocol/src/`, `apps/core/src/`의 `engine/`·`estimate/`·`cube-events/`, `apps/pad-gateway/src/gateway/`, `apps/pad-sim/src/`. 저장소 뿌리의 `test/rules.test.ts`가 강제한다.

| # | 규칙 |
|---|---|
| ① | import 금지: `electron`, `fs`, `net`, `http`, `https`, `child_process`, `worker_threads`, `serialport`, `node:sqlite`(`node:` 접두 포함) |
| ② | `Date.now()`, `Math.random()`, 인자 없는 `new Date()` 금지. 시각은 입력으로 받고 난수는 씨앗 PRNG(mulberry32 등) |
| ③ | 폴더·패키지끼리는 2절 표의 "기댈 수 있는 곳"만 |
| ④ | `protocol`·`core`·`pad-gateway`·`pad-sim`은 순수 폴더 밖에서도 `electron`과 `apps/client`를 import하지 않는다(core와 입력원을 `utilityProcess`로 옮길 수 있게, 1절) |

같은 입력 열이면 같은 출력이어야 한다(REQ-055). 부수 효과는 결과 값(명령 목록)으로 내고 셸이 실행한다.

## 4. 데이터 흐름

```text
패드 USB ─serialport─▶ pad-gateway: gateway.onFrame(buf, t_pc_us)     (pad-sim은 같은 사건을 바로 만든다)
  ─▶ 내부 사건: pad.session · obs(광학 원시 창) · cube.evt · cube.link · cube.rebooted
  ─▶ core: obs에 estimate로 x·y·conf 채움 ───────┐
어댑터 stdout ─▶ window 사건 ─────────────────────┤
렌더러 cube:req ─▶ ipc-check(client) ─▶ app 사건 ─┤
                                                  ▼
                      셸: JSONL 기록 → cube-events.step(state, event)
                            (step 안에서 engine 순수 함수 호출)
                                          │ {state', commands}
          ┌───────────────┬───────────────┼────────────────┬──────────────┐
          ▼               ▼               ▼                ▼              ▼
   db → SQLite 커밋   apply 묶음 →     표시 명령 →        notice·상태 →   ai_member →
   (실패면 아래 0)    어댑터 stdin     표시 렌더러 →      cube:state     AI 조정 →
                                       LED·ICON → USB     (50 ms 모음)   CLI 자식
```

- 쓰는 쪽은 cube-events 한 곳, 한 루프다. 사건은 들어온 순서대로 하나씩 처리한다.
- 커밋이 실패하면 창·표시·알림 명령을 하나도 내지 않는다(REQ-036). 세부는 [03 상태기계](03-상태기계.md) 3절.
- AI 조정은 `ai_problem`을 표시 렌더러에 보내고, 실행 상태를 `cube:state`에 싣는다.

## 5. 개발 환경과 시작점

코드는 이 문서들을 기준으로 이 저장소의 `packages/`·`apps/`·`drivers/`에 처음부터 만든다.

| 항목 | 값 |
|---|---|
| 앱 틀 | Electron 44 + React 19 + TypeScript 6.0, Node 24 |
| 빌드 | `apps/client`를 electron-vite 5(Vite 7)로. main·preload·renderer를 한 설정으로, 렌더러 HMR |
| 라우팅 | react-router 8 `BrowserRouter`. `/` 앱, `/template` 부품 카탈로그 |
| 검사·시험 | ESLint 10 + typescript-eslint, `tsc --noEmit`, Vitest 5 + Testing Library(jsdom). 저장소 뿌리에서 `pnpm check` = 모든 TS 패키지의 lint · typecheck · test |
| 패키지 관리자 | pnpm workspace 하나(2절). 의존성은 정확한 판으로 넣는다. Electron은 특히 `^`·`~`를 쓰지 않는다 |
| 실행 환경 | Electron·esbuild는 OS별 바이너리를 받으므로 Windows에서는 `pnpm install`·`pnpm dev`를 Windows PowerShell에서 한다. WSL에서 설치한 `node_modules`는 Windows에서 쓸 수 없다. Mac에서도 순수 모듈·화면 개발은 된다. 창 어댑터·실제 창은 Windows |
| 포장 | 다음 단계. 포장판은 `file://`로 열면 `BrowserRouter` 경로가 동작하지 않으므로 `app://` 프로토콜로 연다([08](08-동반-앱.md) 9절). 포장 도구와 어댑터 exe를 함께 넣는 방법 [미정 S11] |
| 창 어댑터 | `drivers/win-driver`에서 빌드한 `cube-adapter.exe`를 core가 띄운다. 포장판은 같은 커밋에서 빌드한 exe를 넣는다. 개발 중 exe 경로를 앱에 알려 주는 방법 [미정 S11] |

`/template`은 개발 전용이다. `import.meta.env.DEV`일 때만 경로를 등록하고 배포 빌드에서는 빠진다. 개발 서버(`http://localhost:5173/template`)라 Electron 없이 브라우저로도 본다.

첫 커밋 완료 조건: 저장소 뿌리에 `package.json`·`pnpm-workspace.yaml`과 `apps/client`가 있다, 뿌리에서 `pnpm dev`로 창이 뜨고 "CUBE SPACE"가 보인다, `/template`에 빈 카탈로그 페이지가 있다, `pnpm check` 통과(렌더 시험 1개 포함), `.gitignore`, 뿌리 `README.md`에 실행 방법.

알아 둘 제약:
- 개발판 HMR이 CSP의 인라인 스크립트 금지([08](08-동반-앱.md) 9절)에 막히는지 확인한다 [실측 필요].
- SQLite는 내장 `node:sqlite` `DatabaseSync`. Electron 44 main에서 안 되면 `better-sqlite3` + `@electron/rebuild` [실측 필요].
